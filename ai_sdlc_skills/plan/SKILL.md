# PLAN — Requirements and intent engineering

Turn sources into supported, testable requirements without presenting inferred needs as stakeholder decisions.

## Route and load

Use for material ambiguity, conflicting requirements, scope/non-goals, quality criteria or requirement changes. Route architecture to DESIGN, implementation to BUILD, assessment to TEST and production diagnosis to MAINTAIN.

For stage work, read [governance](../shared/governance.md), [artifact contracts](../shared/artifact-contracts.md) and the [stage procedure](references/procedure.md). A routing-only answer needs no deeper resources. Collect only dependent inputs using [project context](../shared/project-context.md). Read [standards](../shared/standards-register.md) when selecting or discussing a reference baseline and [platform adapters](../shared/platform-adapters.md) when relying on actual host behavior.

## Workflow

Inspect sources and actual authority; reconcile conflicting statements; separate observed problems, inferred needs and solutions; define stable requirements and observable criteria; resolve material decisions; assess change impact and hand off exact revisions.

Use [intent.md](../shared/templates/intent.md) or a documented equivalent preserving IDs, revisions, evidence and status. A clear authorized task, issue and existing repository contracts can suffice for a compatible small change. Formal review is conditional on actual governing authority. Continue all already authorized stages; a handoff alone does not complete the user's broader task.

## Boundaries and exit

A reviewable draft can retain explicit gaps. A baseline/design handoff needs sufficiently supported requirements, measurable affected criteria and any actually required decision evidence. Never invent thresholds, precedence, clauses or approvals.

Act only within existing task/tool/data scope. Report authored, executed, verified and approved states separately. Missing evidence blocks only its dependent claim/action; never fabricate a result, approval or standard clause. Validate current records using ART-1 and exercise relevant [evaluation cases](../evaluations/cases.md).
