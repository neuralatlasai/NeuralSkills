# Documentation profile evaluation

Freeze source, cases and criteria before collection. Give each fresh context the skill entry path and one case, withholding criteria/prior outputs. Permit relevant source/case reads and the assigned Markdown output only; no operational or research commands. Six tool calls/180seconds per case. Use two independent contexts for the two cases. Preserve outputs and any failures.

Review against raw inputs/criteria independently. Check proportional document selection, identity/status, stable trace, practical procedure fields and truthful unverified results. Count words with whitespace splitting; do not score headings as normative IEEE compliance. Existing project conventions take precedence when applicable; these cases supply none.

Run `node quality/saas/validate-saas.mjs` for bounded package structure and link checks. Full normative ISO/IEC/IEEE text and formal assessment are unavailable. Published-company guidance is a source of selected practices, not a universal enterprise mandate or certification. No real application test/deployment is required by this documentation-only evaluation.
