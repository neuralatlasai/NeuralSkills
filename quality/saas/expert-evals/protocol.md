# Bounded expert-depth revision evaluation

This is a four-case diagnostic suite for these two skills on this host. It is not a universal engineering benchmark or a skill quality certification. The evaluated skill versions are preserved 1.0.0 and frozen 1.1.0. Original skills, source maps, citations, and existing evaluation evidence remain intact. Historical `.txt` files are evidence, not independently installed skills.

## Exposure and execution

UI-U1 and BE-B1 are comparative public cases. UI-U2 and BE-B2 are held out. Do not open `holdout/` or `hidden-grading/` or expose their contents to skill authors before the 1.1.0 freeze. The suite author did not read newly authored expert references. Freeze all suite source hashes before agent implementation. Keep the manifest and raw author setup evidence. Root may read held-out task contents only after skill freeze; no further skill tuning against those results without declaring a new cycle and a fresh holdout.

Exactly six fresh implementation contexts: UI-U1/1.0.0, UI-U1/1.1.0, BE-B1/1.0.0, BE-B1/1.1.0, UI-U2/1.1.0, BE-B2/1.1.0. Same parent model/reasoning/tools, no child agents, no shared conversation, 360 seconds and at most 20 nested tool calls per context. Count every invoked underlying tool, including batched tools, toward 20. The supervisor records start/end time and actual call count; on exhaustion stop and retain partial output. Skill reads count. Authoring/setup checks are not implementation trials. Do not score setup as skill evidence.

Each context gets only the selected task, a fresh writable fixture copy, shared wrapper/output contract, the chosen skill entry + its available reference map, and ordinary installed tools. It must not inspect another trial, grading, suite history, or alternative skill version. No package installation, production dependencies, frameworks, external accounts, public upload, or deployment. Native TypeScript/CSS, Node 24 and SQLite only; existing Playwright/Chrome may be used. Both versions receive identical task bytes, fixture bytes, output contract and tools. A requirement may be recorded in a small note; full task schema/coverage bookkeeping is unnecessary beyond the supplied compatible output contract.

Author setup includes known-good repaired control fixtures solely to validate that the checkers can pass; these are not skill submissions and must not be supplied to implementation contexts. All four original fixtures expose faults and all four repaired author controls pass their full checker. One pre-freeze native-browser focus false negative was found by a positive control, corrected before implementation trials, and retained in author evidence. Author evidence includes held-out semantics and remains sealed with the held-out tasks. `public-setup-summary.json` exposes counts only.

For old skill reads map `SKILL.md` to `version-history/1.0.0/<skill>/SKILL.md.txt` and every old `references/X.md` to sibling `references/X.md.txt`. `old-reference-map.json` enumerates exact hash-preserved entries from `../version-history/1.0.0/snapshot.json`. Unchanged assets/scripts remain available at their source location, clearly marked inherited. Never follow a legacy relative reference into a revised reference accidentally. New skill reads map to the frozen 1.1.0 package. Freeze complete selected assets as well as instructions before starting.

## Predefined assessment

First run the independent case verifier against the unmodified fixture; it must expose the named faults and at least one healthy control. Then run it against each submitted artifact without editing its checker or thresholds. Use actual Chromium for UI and actual `node:sqlite` file databases for backend. Each objective check is PASS/FAIL/UNVERIFIED with raw observation. Required failures or unavailable execution prevent an unqualified implementation pass. Preserve agent-added tests separately; independent checks remain decisive. SQLite process restart is not power-loss evidence, and a browser DOM check is not an assistive-technology assessment.

Use `rubric.json` for a blinded categorical review. Strip skill version, trial labels and instructional citations from the submission copy. Reviewer sees task, artifact diff, evidence and anonymized labels; reviewer does not see expected preferred answer. Review causal diagnosis, justified alternative, operating limit/failure boundary, and evidence trace as DEMONSTRATED/PARTIAL/ABSENT with a concrete quotation or code/test pointer. No 1–10 ratings, aesthetics, word counts, metadata size or terminology matching. A shorter valid mechanism can outperform an elaborate answer. Accept alternative mechanisms satisfying all behavioral checks and stated limits. Do not reward mandatory vocabulary or new-reference phrases.

Compare public cases requirement by requirement and report actual tool/time use, independent checks, review disagreements, and material unresolved boundaries. Held-out results are separate transfer observations, not a paired superiority claim. Two comparative observations and two held-out observations do not justify statistical/general performance claims. Report incomplete contexts and infrastructure failures separately from code defects. Reruns must be declared with reason and original evidence retained; never silently replace the first result.
