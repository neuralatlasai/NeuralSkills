## Diagnosis and causal evidence

The original load() assigned every resolved response directly to items and every rejection to status, regardless of query age. The browser baseline completed B before A and displayed `Old result` instead of `New result`; this distinguishes missing request ordering from a network failure or incorrect current response. Baseline also observed two searches during composition (expected zero), lost input focus during Arrow navigation, root mutation after disposal, and document overflow at 320px. Source inspection identifies unconditional input.blur(), missing composition handlers, missing disposal guard/listener removal, input min-width:360px and nowrap options as separate causes. See [baseline-results.json](baseline-results.json), preserved unchanged. Baseline was the first five tests; four supplemental tests were added afterward.

## Choice and limits

Plausible alternative: debounce searches. It is useful if a real service needs reduced request volume, but it cannot stop an already issued old promise from settling after a new one, and it does not establish composition commit semantics. A request-generation check directly fits this deterministic injected transport; AbortSignal is an optimization, not the correctness boundary. Rejected adding a global state library/cache service: only one component owns ephemeral query/results state and the fixture explicitly has no shared service or application architecture requirement.

Implemented: ordering/composition/focus/keyboard/retry/disposal/layout fixes, semantic hidden/active state, optional pointer selection, focused browser tests. Inherited: exported mount and Search signatures, fixed element IDs, roles, demo deterministic timing. demo.ts documents its intentional cancellation-ignoring behavior; index.html adds status association and initial hidden list. Simulated: transport completion/failure ordering and composition events. Unperformed/UNVERIFIED: physical Japanese IME, assistive technology, non-Chromium engines, zoom/reflow beyond stated viewports, automated accessibility scanner, measured color contrast, static TypeScript compilation, production API and field performance. No conformance or real-user performance claim. All five supplied requirements have executed passing fixture evidence; these broader limits remain explicit.
