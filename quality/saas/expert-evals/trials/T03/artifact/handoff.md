# T03 handoff

Implemented the bounded local reservation repair using supplied historical backend-engineering 1.0.0 text and the allowed BE-B1 fixture. No package installs, network, production changes, delegation, or edits outside this artifact. Requirements are from public/BE-B1/task.md. Node v24.12.0 and its real SQLite 3.50.4 engine were exercised against file-backed databases.

The original read/check/await/unconditional-decrement path let two calls each observe five units, then both reserve four. [baseline.txt](baseline.txt) preserves six failed checks. [baseline-state.json](baseline-state.json) records red stock=-3, two receipts and two events, and the separate failBeforeCommit database with stock=1 but no receipt/event. These persisted states distinguish transaction/race defects from an unavailable SQLite engine or mere response formatting. A global key lookup also returned the old result for different parameters and did not durably retain sold_out outcomes. The original independent-process race happened to pass once; that result does not erase the deterministic same-process oversell.

service.ts owns validation, SQLite connections and the complete local transaction. BEGIN IMMEDIATE acquires the file's SQLite writer lock before replay/stock reads. An atomic conditional decrement and nonnegative STRICT inventory constraint protect stock. Tenant+operation+key receipt uniqueness, immutable stored parameters on this path, durable reserved/sold_out receipts, unique local events and a tenant-inclusive event foreign key prevent duplicate or mis-scoped effects. Each accepted reservation, receipt and event commits in the same transaction. readState uses a read transaction for a consistent snapshot. All SQL values are bound; only the fixed numeric busy-timeout constant appears in SQL text. Every connection is closed in finally, including open/setup failures; transactions roll back before retry or exit.

`node run-evidence.mjs` executed 9 focused checks per run, three runs, plus the edge suite, all with exitCode=0. Raw stderr retains the inherited experimental SQLite and typeless-package warnings. Full suite elapsed times were 2642.60,2645.72,2949.07 ms (median2645.72, range2642.60-2949.07); these are local test observations, not a throughput benchmark. The earlier final-1.txt run also passed. baseline.txt remains unchanged. inspect-baseline.mjs was executed to extract baseline-state.json. Tests retain synthetic SQLite files under evidence/.

A plausible alternative is an optimistic conditional update plus uniqueness-conflict reconciliation in deferred transactions. BEGIN IMMEDIATE fits this short, single-file transaction better: it serializes receipt checks before the write and avoids a read-to-write upgrade race. Optimistic transactions could be appropriate after measured writer contention justifies their retry complexity and complete-transaction retry behavior is verified. A broker/outbox dispatcher, distributed lock or server database is unnecessary: the event is a local SQLite row participating directly in the same commit, with no remote consumer/effect requirement.

Compatibility: init/reserve/readState exports and command/result statuses are preserved. reservationId is now an opaque UUID. Receipts/events gain an operation column and composite identity; readState still returns stock/receipts/events. This is a new disposable-schema fixture, not an existing-database migration. Callers must use init on a fresh file. Connections and SQLite primitives are inherited; transaction/validation/schema/replay handling and focused tests are implemented/changed. Authentication, network transport, production migration, remote delivery, disk-full, forced process death/power-loss and backup restore were not performed and are outside this local task; none is claimed verified. File/OS access and correct trusted tenant selection remain caller responsibilities. readState materializes all records; retention growth is unbounded by design for this fixture, so a production service would need an explicit replay-retention and paginated inspection policy.

Applied areas are API contract/validation, local event identity, schema/query/transactions and failure/replay verification. Edge/network, external integration, distribution and deployment mechanisms are out of scope because this fixture is exclusively a local storage path. No standards certification or universal capacity guarantee is claimed.
