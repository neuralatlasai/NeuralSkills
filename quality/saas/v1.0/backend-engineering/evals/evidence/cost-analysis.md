# Cost model for the demonstrated local backend

Source: `scripts/service.mjs` at the build identified in the final integrated/load/network/smoke records. This is analysis of that finite fixture, not a production capacity or recovery guarantee. Actual measurements and hardware are in `integrated/load-results.json` and its timestamped raw files. Estimates and unknown terms below are not measured results.

## Variables and operating range

`N` is stored items; `I_t` is a tenant's idempotency rows; `J` pending dependent jobs; `B` request bytes; `R` serialized response bytes; `K` list results; `C` admitted active requests; `Q` queued requests; `P` server partitions. The load fixture seeds N=40 with32/8 tenant split,80/20 tenant traffic,75% read-one/25% list, observed K=3 and maximum K=10. P=1. Encoded JSON body B≤2048, JSON depth≤4; headers≤8192bytes; C≤2, Q≤4 with90ms queue age. Each ingress/app has32 socket admission cap. High-water marks are backpressure thresholds, not hard total memory caps.

## Critical paths

| Path | CPU/auxiliary and retained space | Database, network and amplification | Limit / failure / verification |
| --- | --- | --- | --- |
| Create/retry | Parse/validate/canonicalize/hash O(B), serialize O(R); bounded request/response workspace, plus retained operation/item/job rows | Auth lookup, unique operation lookup, transactional indexed inserts and local WAL/index writes; network includes TCP/TLS and2 local request hops | Commit loss resolved by durable scoped identity; same key/different params denied; current authorization checked on replay. Actual duplicate/lost-response and replay regression evidence; no whole-operation O(1) claim. |

Exact physical I/O/rows examined unavailable. |
| List | Indexed seek plus O(K) materialization and O(R) serialization; bounded K+1 fetched rows | Actual plan reports `SEARCH items USING INDEX sqlite_autoindex_items_1 (tenant=? Deleted public representation is not replayed; minimal historical IDs have an explicit fixture-retention policy. |
| Worker | Bounded one-job selection and local transactional effect identity; durable effect/attempt rows retained | Effect insert and acknowledgement are distinct boundaries. Child process exits after commit and fresh process replays against real SQLite uniqueness | Exactly-one local ledger effect only; external effects, distributed fencing and long replay-horizon storage unverified. |
| Restore/migration | At least O(database bytes+replayed/reconciled state+validation); keys/config/permissions and deleted-state checks are part of usable recovery | Actual SQLite online backup/restore and additive v3 compatibility checks; no remote transfer, PITR, multi-node failover or power-loss test | Measured local restore includes the exercised validation path; cannot extrapolate to production RPO/RTO or assume backup file existence proves recovery. |

Storage is not constant: items, operation results, pending jobs, effect identifiers, deletion records and their indexes grow with accepted work; WAL/checkpoint and backup copies add space and I/O. A model is `S≈N×s_item + I×s_operation + J×s_job + E×s_effect + D×s_tombstone + indexes + WAL + backup headroom`, with actual encoded sizes/amplification measured for a deployment. The load fixture is read-heavy after seeding; it does not measure sustained write growth, large tenant cleanup or full-disk recovery. Production retention/disk quotas require a separate contract.

## Memory and connection envelopes

Use `M_required=M_base+C*m_active+Q*m_queued+M_cache+M_buffers+M_runtime`. Here C=2 and Q=4 are enforced application limits; payload/headers/cache/telemetry limits constrain terms, but TLS/native socket buffers, stacks, runtime/GC and database page/cache memory remain part of the envelope. Individual term coefficients were not isolated; total process RSS is sampled in raw load results. The generator and service share a process, and process maximum RSS is a cumulative observation. It is not a per-request allocation measure or a proof of a production memory ceiling.

Use `C_DB,total=Σ(active_instances_j*pool_limit_j)+C_workers+C_maintenance`, including starting/terminating/coexisting instances. The ordinary local service has1 DatabaseSync connection; the separate worker adds1 while active. Backup destinations, restored/coexisting service connections and maintenance must be counted separately. There is no client/server DB pool in this fixture and no PgBouncer test; application permit exhaustion is not database-pool exhaustion.

For stable matched boundaries, `L=λ_admitted*E[W]`. The short scripted windows record demand and completions, but no time-integrated admitted occupancy and same-population mean residence series were collected. Do not substitute p50/p99 or generated-request latency for E[W], or use this formula to claim a measured p99/occupancy guarantee.

## Measurement basis and limits

The captured machine is Windows x64, Intel i5-1135G7 with8 logical CPUs and16934494208bytes total memory, Node24.12.0, SQLite3.50.4 and OpenSSL3.5.7. Three repetitions of six frozen open-arrival scenarios include normal, sustained, burst, overload, injected dependency failure and recovery. The generator cap24 and its dropped arrivals are explicit. All generated-response latency samples include failed/rejected demand; dropped arrivals have no response latency. CPU/RSS/event-loop observations include generator work. Fresh TLS connections, warm-up3 and cache retention between scenarios are declared; OS/disk-cold behavior is not controlled.

The final load record accounts for822 intended=582 generated+240 dropped, and582 outcomes=366 useful+108 rejected+108 failed;0 retries and0 client timeouts. These finite local samples and empirical order statistics are not a production SLO, a distributed scaling result, or statistical confidence. No optimization speedup is claimed without a comparable before/after experiment; B03 separately evaluates a concrete query optimization on its own frozen workload.
