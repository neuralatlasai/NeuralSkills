Node 24.12+ built-ins. Copy to trial/artifact; run `node probe.mjs race.sqlite` with a fresh filename. The probe releases two asynchronous callers after both reads and prints actual state. Preserve the hooks; afterWrite throws in a separate fault test and performs no external effect. SQLite must remain real, including file-backed reopen checks.

This trial repairs `reserve(db, request, hooks)` while retaining the exported API and response shapes. Quantity must be a positive safe integer (400 otherwise); missing tenant/item is 404; stale version or insufficient stock is 409. Tenant/item values scope every stock access and allocation insertion. The fixture accepts an already trusted tenant argument; authentication and caller-to-tenant authorization belong to a surrounding application and are not implemented here.

The initial read and asynchronous `afterRead` hook occur before the write transaction. `BEGIN IMMEDIATE` then owns the write boundary. A conditional UPDATE checks tenant, item, expected version and sufficient quantity again, decrements stock and increments version; its returned values define the 201 response. The synchronous `afterWrite` hook and allocation INSERT execute in the same transaction. A thrown hook or failed INSERT rolls the entire transaction back. No application mutex or external package is used. The caller must supply an idle connection and must not begin/commit/roll back transactions from hooks.

Run `node verify.mjs` from this directory. Each execution creates fresh file-backed databases and writes `verification.json`. The supplied probe also remains runnable with a fresh SQLite filename. Verification uses Node v24.12.0 and SQLite 3.50.4: three same-connection races and three two-connection races, close/reopen checks, afterWrite rollback and explicit retry, invalid quantities/versions, tenant/item scope, missing resources, insufficient stock, afterRead rejection, integrity/index checks, a held SQLite writer lock followed by explicit retry, and an allocation-insert trigger failure followed by rollback/retry.

`baseline-race.json` records the unmodified fixture returning two 201s and inserting two allocations. `verification-initial-failure.json` preserves a verification defect: the first test incorrectly expected version 2 to conflict even though version 2 was current after a successful retry. That test was corrected to stale version 1, without changing the implementation or weakening the version rule. `verification-before-contention.json` preserves the earlier passing run; `verification.json` is the final 13-check run.

Limits: SQLite serializes writers on this local database file. The inherited busy_timeout is 200 ms; a held writer produces the native SQLite locked error and no mutation, with a caller retry after the holder rolls back demonstrated by the verifier. There is no automatic retry, no queue/admission policy, no multi-host database claim and no exactly-once response/replay guarantee. Synchronous SQLite work can block the Node event loop. Hooks are caller-controlled; afterRead has no imposed deadline, and afterWrite is synchronous and intended only for the supplied fault injection. An async afterWrite callback or external hook side effects are outside this contract. Transactions cover stock and allocations in this SQLite file, not external effects. Successful close/reopen is observed; power-loss durability, backup restore, disk failure and ambiguous commit acknowledgement are unverified.

Cost model: with N stock rows, A allocations and B tenant/item bytes, primary-key lookup and update use the composite index (observed EXPLAIN plan); B-tree operations depend on log N/log A and B, plus journal/page writes and commit I/O. Each successful attempt performs one preflight SELECT, one conditional UPDATE and one allocation INSERT in one short transaction, returning K=1 result. A conflict after the hook adds one existence SELECT. JavaScript result storage is bounded by one row plus caller hooks; SQLite cache and file/journal sizes are not measured or bounded by this patch. This is a correctness experiment, not a throughput or latency benchmark.
