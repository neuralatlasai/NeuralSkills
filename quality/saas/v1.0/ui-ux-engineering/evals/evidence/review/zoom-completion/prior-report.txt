Evaluation method and limits

There are 18 actual implementation observations: C01 and C06 each have 3 baseline and 3 skill runs (12 comparative), and C02/C03/C04/C05/C07/C08 each have 1 skill-only run (6). C07/C08 are the 2 held-out cases. No planned trial is missing. Comparative implementation contexts were fresh with no history fork and inherited identical model configuration; the exact model identifier, actual tokens and monetary cost are not exposed. Tokens/cost remain null. The [freeze check](evidence/review/freeze-check.json) independently recomputes all 44 frozen hashes: all remain unchanged. The separately added [coding note](../references/coding-standards.md) clarifies the existing IEEE basis; it does not alter the frozen instruction core or establish ISO/IEEE conformance. Held-out cases informed this final grading only, with no instruction tuning.

A separate evaluator reviewed raw evidence and artifacts, compared reference/render images, checked source constraints and authored independent runtime spot checks. Arm blinding was infeasible because paths and task context exposed arm identity. The corrected [independent runtime run](evidence/review/independent-runtime.json) passes 43 scoped assertions across all 12 comparative artifacts plus exact C03 375px reflow: clipboard payload/duplicate guard/rejection/retry/reset, both C06 race sequences, page overflow and runtime exceptions. Initial harness selector/root errors remain retained and diagnosed. Original self-PASS alone was not accepted as proof: statuses use the concrete logs/assertions/source or explicitly unavailable runtime. Implementation wrappers supplied requirement IDs without their frozen meanings; several agents assigned different meanings, especially C07/C08. This is an evaluation-wrapper limitation. The assessment remaps actual task evidence to canonical frozen requirements instead of trusting raw ID labels. It does not silently rewrite the raw results.
