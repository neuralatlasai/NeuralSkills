# Database, state invariants and distribution — B4

Activate for L10–L14. Inputs: actual engine/version, schema/migrations, roles, workload/access patterns, representative cardinality/skew, plans and invariants. B3 defines operations; B5/B7 define external/restore boundaries. Output executable schema/adapters and verification for the selected engine. Read its actual documentation; do not transfer PostgreSQL guarantees to SQLite, MongoDB or a proxy.

| Requirement | Mechanism | Operating limit | Failure mode | Verification |

| L10 Modeling/DDL invariants | Select IDs, tenant-inclusive uniqueness, types/precision/collation/time, null/defaults, relationships and supported PK/unique/FK/check/exclusion constraints. Normalize or denormalize from access/invariant needs; own schema and compatibility. | Domain ranges, key/index widths, migration/backfill/lock and partition bounds. Database errors require engine-aware classification. At weaker isolation, an atomic in-place update can protect a single-row invariant; it does not prove arbitrary multi-row serializability. Names such as REPEATABLE READ vary across engines. Never retry an isolated statement from an aborted transaction as if prior reads remain valid. External messages, objects or provider effects are not committed by a local DB transaction unless an actual coordination protocol covers them.

For optimization, retain the original query/workload, falsifiable bottleneck, expected effect and correctness checks. Compare like-for-like at least three important runs with plans/cardinality/skew/cache/config and raw outcomes; account for write/storage cost of a new index. Neither a generic index rule nor a selected plan screenshot proves a universal speedup. If cache state, rows examined, physical I/O or lock wait cannot be observed, name that limitation.

Failure handling: stop unsafe schema/data work, retain original data/evidence, rollback within supported boundaries or execute a documented forward repair. Verify old application behavior against the post-migration schema before describing rollback as feasible. Backups and replay must preserve tenant permissions and deletion state as well as values.
