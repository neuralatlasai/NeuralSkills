# Conditional subskill contracts

The eight procedures share the task context. Dependencies are outputs: design-time constraints can precede implementation; runtime verification follows it. A small task may keep outputs in one short record. No module adds tool authority or changes the requested scope.

| Module | When to activate; inputs; dependencies | Procedure and output | Resource limits; failure handling; verification |
| --- | --- | --- | --- |
| B1 Intake/contracts | Every backend task; request, repo, actual tools/evidence; none | Inspect actual path/versions, establish objective, trust/state owners, invariants, workload and checks; map L01–L24 and choose active modules. Output one sourced task contract, coverage dispositions and decision tuples. | Research/questions proportionate to consequential unknowns. Conflicts need consequence+alternative; missing evidence blocks its dependent claim. Verify full index present, sources separated from assumptions and output matches scope. |
| B2 Edge/identity | Changed or implicated DNS, connections, TLS, proxy, callers/protocol; context+topology; B1 | Map every hop and trust transition; define resolver/cache/discovery, transport/socket budgets, certificate identity, ingress normalization and authorization. Output transport/identity contract and probes. | Connection/body/header/deadline/stream bounds; no verification bypass. Diagnose failed resolution/rotation/forwarding rather than disabling controls. Verify real selected transport, rejected bad credentials/certs, endpoint replacement and cleanup; unavailable hops unverified. |
| B3 API/domain | API, CRUD, workflow or parser change; schemas, callers, invariants; B1+B2 policy | Specify each supported operation, errors/projection, state transitions, atomic preconditions, deadline/transaction ownership and side effects. Output contracts and working path integrated with B4/B5. | Bound input, response, batch and retries. Conflicting parameters or uncertain effects require defined errors/reconciliation. Verify lifecycle, concurrent duplicate/version races, bypass attempts, malformed/expensive requests and schema compatibility. |
| B4 Data | Storage/query/schema/transaction/pool/distribution change; schema, engine/version, plans/workload; B1+B3 invariants | Choose constraints/queries/isolation and privileges by actual engine; analyze DDL/DML/DQL/TCL/DCL, access paths, storage amplification and routing/replication when justified. Output migrations, adapters, plans, roles and recovery boundaries. | Pool/statement/lock/transaction limits, bounded rows/locks, maintenance and surge connections. Roll back/retry complete transactions only when safe; commit ambiguity stays unknown until reconciled. Verify real DB constraints, contention, permissions, pool reuse and applicable failover. |
| B5 Async/integration | Cache/derived state/event/job/file/search/external tool; state/replay contracts; B1+B3/B4 boundaries | Specify source authority, event/operation identity, ordering, publication/effect/ack boundaries, durable ownership/checkpoints, credentials/schema/egress and cleanup. Output bounded adapters and replay/recovery behavior. | Bound cache, backlog, in-flight, age, bytes, result size and retries. Failed compensation or external effect may remain uncertain; quarantine and reconcile. Verify duplicates/crashes, stale owner, out-of-order/revoked data, slow consumers and malicious outputs. |
| B6 Runtime/capacity | Runtime/resource/latency/throughput/scale or costly path; actual hardware/workload/profile; B1+affected mechanism contracts | Model CPU/memory/I/O/network/amplification and deployment connections; identify bottleneck, admission and scale policy, then implement/profile comparable change. Output cost envelope, workload/load accounting and measured operating range. | Bound processes/tasks/queues/pools/FDs/buffers; preserve all offered demand categories. Overload sheds/rejects predictably and recovers. Verify starvation/leaks/cancellation/termination, ramp/burst/sustained/failure/recovery; do not infer p99 from averages. |
| B7 Operations | Deployment, reliability, incidents, telemetry, security/retention; topology, state classes, SLO/RPO/RTO; B1+active path | Define containment, secret/cert uptake, isolated restore/reconciliation, old/new migration compatibility, readiness/draining, audit/telemetry loss and artifact identity. Output working changes, runbooks and exercised recovery/rollout evidence. | Bounded retry/export/backfill/termination/restore envelopes and authorized blast radius. Stop unsafe dependent action, retain failures and forward-repair path; no fabricated rollback. Verify outage/rotation/restore/canary/shutdown, old app against new schema, denied paths and data lifecycle. |
| B8 Verification/delivery | Every task; actual artifacts, context, raw checks; active module outputs only | Trace requirement→mechanism→limit→failure→test, execute appropriate layers, review integrated outcomes, repair/retest and deliver reproducible evidence. Skill authoring additionally uses fresh/held-out/baseline cases. | Freeze gates/budgets before results; start with three substantive revision cycles, expand only for a named failure. Required unverified/fail prevents unqualified completion. Verify commands/resources exist, scripts executed, denominators/raw samples preserved, exact support limits stated. |

Procedure-specific coverage details are in the entrypoint's directly linked references. Activate distributed mechanisms only for a stated invariant/workload/failure need; the index is a coverage obligation, not a demand to install every technology.
