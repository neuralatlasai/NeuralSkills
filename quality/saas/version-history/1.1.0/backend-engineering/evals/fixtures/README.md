# Local executable fixture

Run from this skill package with Node24.12 or newer. Captured evidence uses Node24.12.0, experimental `node:sqlite` SQLite3.50.4, and Git-bundled OpenSSL3.5.7. No npm install or network dependencies are needed. Set `OPENSSL_PATH` and `TYPESCRIPT_PATH` when host locations differ. The TypeScript compiler is used only for the typed contracts; the runtime implementation is JavaScript with syntax and real integration checks.

`npm run check` checks runtime syntax and strict contract types. `npm test` executes13 integrated cases. `npm run network` executes real local UDP DNS queries and endpoint replacement. `npm run load` runs three repetitions of six frozen open-arrival workloads. `node scripts/smoke.mjs` runs those suites in order and checks each CLI's success and failure paths. Evidence is written under `evals/evidence/integrated`; each full attempt has a distinct timestamped directory. Failed earlier attempts remain present. Summary files at the evidence root identify the latest completed run.

The HTTPS endpoint validates against an ephemeral fixture CA. The ingress normalizes forwarding headers and connects over HTTP to a secret-protected IPv4 loopback application socket. The second hop is deliberately unencrypted loopback; there is no claim of encryption beyond this host. Private test key files are removed after generation and keys remain only in process memory. The fixture changes no global trust settings and never disables TLS verification. `npm run certs -- <directory>` verifies local issuance and leaves public certificate artifacts; it deliberately does not retain private keys for reuse.

The REST API serves `POST/GET /v1/items`, `GET/PUT/PATCH/DELETE /v1/items/:id`, `POST /v1/items/:id/adjust`, and scoped `GET /v1/jobs/:id`. Mutations require JSON, bounded fields, and authorization. POST requires `Idempotency-Key`; versioned changes require numeric `If-Match`. PUT clears an omitted description and requires name and quantity; PATCH preserves omitted allowed fields and rejects null values for nonnullable fields. Create returns201 with Location/ETag. Delete is hard deletion, records a tombstone, cascades pending jobs, and a repeated delete returns404. List is ordered by UUID ID using a signed caller-scoped cursor, maximum10 items. Inserts after the cursor can appear on later pages; snapshot pagination is not promised. Bulk/upsert/search/GraphQL/gRPC/streams are unsupported in this fixture.

Every mutation revalidates the active Bearer credential, current role, field permissions and current object inside one synchronous `BEGIN IMMEDIATE` transaction after any body/admission/work await. PATCH fills omitted fields from that current transactional row. Limited-owner predicates also guard the SQL mutation. Replays recheck current authority and return the current authorized representation, which can differ from the original response while preserving the original logical effect. After deletion, replay returns a minimal410 Problem Details response; it never recreates the item or returns old resource fields. Deletion replaces matching durable replay payloads with `{id,deleted:true}`, retaining the tenant/key/actor/parameter-hash operation identity. Effect-ledger records retain only tenant/job/item identifiers for the lifetime of this local fixture; they are administrative replay/audit metadata, have no public retrieval path after job deletion, and require an explicit production retention policy.

Schema v3 installs database INSERT and UPDATE guards requiring SQLite storage type `integer` and range0..100000 for quantity, and integer1..9007199254740991 for version. These cover raw writers and additive migration of the legacy table; SQLite's `INTEGER` affinity by itself does not enforce this. Migration refuses existing fractional or out-of-range rows instead of coercing them. API preconditions also reject unsafe integers. Cursor parsing requires exactly two canonical base64url segments, a signed caller scope and a UUID-shaped last ID. Authentication requires an actual case-insensitive Bearer scheme.

Credentials are **synthetic fixture-only bearer strings**, seeded as `fixture-token-a`, `fixture-token-b`, `fixture-token-limited`, and `fixture-token-admin`. They map to two tenants and editor/limited/admin policies in SQLite and can be revoked/rotated. These are no production identity provider, OAuth/OIDC, JWT issuer/audience/expiry or session implementation. SQLite file access is a privileged administrative boundary. Application SQL is tenant scoped and jobs have a tenant-inclusive foreign key; database DCL/RLS/session-pool separation is not implemented by SQLite. Database pool exhaustion is NOT_APPLICABLE: there is one synchronous SQLite connection. The integrated exhaustion case tests the application admission permits and bounded queue.

The application admits2 active requests and queues at most4 for90ms; request-body/work deadline180ms is propagated from application admission start, body limit2048 bytes, JSON depth4. Ingress and application each cap concurrent sockets at32, listen backlog32, header bytes8192, stream high-water bytes2048, TLS handshake deadline500ms. Socket rejection beyond the connection cap can surface as a connection close. Synchronous SQLite operations cannot be preempted by JavaScript and have100ms busy timeout. Client and ingress timeouts are separate. Responses/errors and test datasets are small; the bounded cache has8 entries and telemetry queue16, while persistent inventory/idempotency/jobs/effects/deletion tables grow with accepted work and need a production retention policy. No production memory envelope is inferred.

The worker commits its local SQLite effect ledger before acknowledgement. A separate worker process deliberately exits77 after that commit; a new process replays and deduplicates the same job. Exactly-one-effect scope is that SQLite unique `job_id` boundary. External effects, power loss, leases, distributed consumers and brokers remain UNVERIFIED or NOT_APPLICABLE. Cache, database-dependency and telemetry outages are explicit application fault seams. The normal path really uses native TCP/TLS and a disk-backed SQLite database; those fault seams do not simulate physical disk or collector/network failures.

The DNS test runs a controlled authoritative UDP server and Node's actual `dns.Resolver`. It advertises A TTL1second, caps the application positive cache at500ms, and uses an explicit80ms application negative cache. The NXDOMAIN response contains no SOA, so this proves the declared application cache, not RFC2308 recursive-resolver negative caching. Endpoint replacement switches127.0.0.1 to127.0.0.2, verifies stale refusal, measures discovery-to-use, and observes50 new TCP connections and socket release. IPv6, QUIC, NAT and descriptor pressure are unverified.

The load generator schedules open arrivals independently of responses and drops intended arrivals when24 generator requests are in flight. Every generated request is classified, and all generated-response latencies include rejection/failure/timeout samples. Dropped arrivals are counted separately because they have no response latency. It uses fresh TLS connections, one process with the server and generator,40 inventory rows and80/20 tenant skew. Results cannot establish distributed scaling, production capacity, filesystem-cold behavior or optimization speedups.
