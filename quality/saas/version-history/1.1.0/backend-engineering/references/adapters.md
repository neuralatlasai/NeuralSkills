# Supported runtime and adapter boundaries

Discover actual tools and versions at execution. Metadata does not supply credentials, services, protocol capabilities or deployment rights. The core is portable Agent Skills Markdown. No host-specific metadata is required; no cloud account, package installer, global trust modification or production deployment is performed by this package.

| Adapter | Actually evaluated configuration | Limit / failure / verification boundary |
| --- | --- | --- |
| Runtime | Node **24.12.0**, Windows x64, native `.mjs` fixture | Requires Node24.12+ API compatibility; only the captured version is demonstrated. Runtime JavaScript has syntax and integration tests; typed fixture contracts alone receive strict TypeScript **6.0.3** checks. Do not describe the runtime as completely statically typechecked. |
| Real database | `node:sqlite`, SQLite **3.50.4**, file-backed WAL and selected constraints/transactions | Node API reports experimental/active development. One synchronous connection,100ms busy timeout; JS cannot preempt a running synchronous DB call. App admission/queue exhaustion is tested; a PostgreSQL/MySQL connection pool is not. No SQLite SQL-role grants/RLS/session pooling claim. |
| Transport/ingress | Native HTTP/1.1 over TCP; HTTPS ingress requires at least TLS1.2 and advertises `http/1.1` ALPN; Git OpenSSL **3.5.7** issues ephemeral fixture certs | Real chain/host/expiry rejection and running certificate/credential replacement are exercised. Ingress→app hop is secret-protected IPv4 loopback HTTP, deliberately unencrypted on one host; no general end-to-end encryption or production PKI claim. No global CA trust/verification bypass. |
| DNS | Controlled local UDP authority, actual Node `dns.Resolver`, A TTL1s; application positive-cache cap500ms and negative cache80ms | Test changes127.0.0.1→127.0.0.2, stale refusal, replacement-to-use delay, timeout/slow peer and TCP release. NXDOMAIN has no SOA: application negative caching is tested, not an RFC2308 recursive resolver. Internet DNS, IPv6, QUIC, NAT and FD-pressure claims remain unverified. |
| Identity | Synthetic fixture bearer strings mapped to tenant/actor/role/active state in SQLite | Rotation/revocation and function/object/field checks are real local tests. These are not production credentials, OAuth/OIDC, JWT issuer/audience/signing-key or browser-session/CSRF coverage. Privileged filesystem/DB access is outside the untrusted API-caller boundary. |
| Cache and telemetry | Bounded in-process cache8 entries and telemetry queue16; controlled fault seams | Tests exercise permission scope, invalidation, fallback/admission and loss visibility under injected seam failures. They are not Redis, CDN or OTel Collector outage tests. Persistent rows grow with accepted work; a production retention/disk envelope must be supplied for deployment. |
| Durable worker | Real SQLite job/effect ledger; separate process exits after local effect commit, fresh process replays | Unique local effect identity is demonstrated. No global exactly-once, external-effect resolution, broker, distributed lease/fencing or workflow-engine guarantee. |
| Recovery/deployment | Compatible legacy repository against additive SQLite migration; bounded local drain/shutdown and isolated backup restore | Actual local process/database evidence, not Kubernetes rollout, multi-node failover, power-loss durability, PITR or regional DR. Report measured restore steps and gaps rather than a production RTO. |
| Protocol/integration guidance | Conditional procedures for GraphQL, gRPC, SSE, WebSocket, object/search stores, external APIs/webhooks and MCP | No turnkey/live adapter is claimed for these protocols by the integrated fixture. Fresh skill tasks may demonstrate narrower behavior; their evidence does not establish an untested SDK/provider. MCP current source route resolved2026-07-28; verify selected deployed revision/SDK independently. |

Use `OPENSSL_PATH` and `TYPESCRIPT_PATH` for actual local binaries on another host. Scripts do not download them. The environment here blocks npm registry requests and Python; Node built-ins and existing tools permit the demonstrated path without changing system policy. Missing tooling is a specific unverified check, not successful execution.

The [fixture instructions](../evals/fixtures/README.md) give runnable commands and exact API/limits. Never copy synthetic fixture credentials into a real service. Artifact evidence is scoped to isolated test data. Reassess all operating limits against real deployment/client/data needs.
