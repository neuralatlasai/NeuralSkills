# Edge, transport and trusted identity — B2

Activate for L01–L05 or implicated parser/security boundaries. Inputs are the actual path, callers, supported clients/proxies, threat model, versions and workload. B1 supplies requirements; B3 supplies operation semantics. Output a hop-by-hop contract and probes, not merely a diagram. Carry the five decision fields below into the shared context. Read only relevant primary sources from the source register at execution.

| Requirement | Implementation mechanism | Operating limit | Failure mode | Verification |
| --- | --- | --- | --- | --- |
| L01: reach current authorized endpoint | Map public/internal zones, OS vs library resolution, service discovery and routing; specify positive/negative cache policy, TTL handling, refresh and replacement ownership. Select TCP or QUIC, IPv4/IPv6 and egress boundaries for actual clients. | Record DNS/discovery/connect deadlines, cache lifetimes and maximum replacement-to-use delay; resolver APIs may expose different TTL/cache behavior. | NXDOMAIN cached too long, stale address, route/family mismatch, unauthorized destination, discovery updates bypassed by existing pooled sockets. | Failed/negative resolution; change/retire endpoint while connections exist; measure when this application actually uses replacement, not when DNS changes. Label injected resolver mocks separately from real DNS/TCP. |
| L01: bounded connection lifecycle | Reuse connections where safe; define connect/read/write/idle deadlines, cancellation, half-open detection and socket cleanup. Inspect kernel/runtime and load-balancer behavior. | Budget live/idle sockets, FD headroom, listen backlog, NAT mappings/ephemeral ports and churn per process/deployment. A timeout event may need explicit abort/destruction in the selected runtime. | Slow/unreachable peer, orphan sockets, port/FD exhaustion, burst reconnects or half-open retention. | Repeated establishment/abort, stalled peer and close/drain tests; count sockets/handles and failures before/after; verify cleanup and recovery under declared workload. |
| L02: authenticated confidential transport | Follow RFC 9325 subject to required compatibility; configure version/cipher policy, chain and hostname validation, trust, SNI/ALPN. Document termination and every following hop; mTLS only when identity model requires it. | Certificate validity/renewal lead time, key access, allowed client versions, session/connection lifetime and rotation uptake interval. HSTS/subdomain policy depends on real domain readiness; do not preload a fixture domain. | Expired/untrusted/wrong-host certificate, failed renewal, stale trust/key, plaintext unexpected hop, replay of early data. | Bad-certificate rejection, new-connection rotation fingerprint/identity, renewal failure and per-hop encryption; distinguish existing connections from new TLS handshakes. Do not disable verification. Reject state-changing early data unless a supported replay-safe contract exists. |
| L03: normalize and route ingress safely | Declare L4/L7 ownership, host/path routing, upstream/discovery, trusted proxy addresses and forwarded-header rewriting. Keep framing/normalization consistent; private origin and cache keys include authorization variance. | Header/body/decompressed bytes, header/request/connect/idle time, retries, connection/admission and cache bounds. Do not multiply retry budgets across gateway/client/workers. | Spoofed client identity, request smuggling, oversized/slow request, private-response cache leak, retry amplification or traffic sent to drained backend. | Spoof forwarding headers; conflicting framing/malformed requests; slow/oversize input; cross-user cache tests; remove backend and test persistent connections, health, load distribution and bounded draining. |
| L04: identify caller and enforce authority | Choose browser session, OAuth/OIDC, service identity or scoped credential from callers. Validate token kind/algorithm/issuer/audience/expiry/signature and signing-key lookup as applicable; distinguish access and ID tokens. Derive tenant from trusted identity+policy and authorize function/object/field per path. | Credential/session lifetime, revocation/renewal and key-cache bounds, delegated scopes, clock skew and compromise response. Never accept tenant/header/body assertions as authority. | Forged/expired/wrong-audience/revoked credential, cross-tenant object ID, mass-assigned privileged field, confused deputy or stale authority on cached/replayed results. | Invalid/expired/revoked/wrong-audience credentials, key rotation, direct API/repository/job/result accesses and field denial. Reauthorize idempotent replay and cache hits. A privileged DB/file owner may bypass application controls: disclose that trust boundary. |
| L04: browser credential boundaries | Define secure cookie attributes, CSRF control and session logout/renewal when cookies are used. Use explicit CORS origin/method/header/credentials/preflight policy for actual browser callers; CORS is not access control. | Origin allowlist and credential scope; public anonymous resources may have different CORS needs. Never reflect arbitrary origins with credentials. | Hostile origin reads or mutates with ambient credentials, token leaks, logout leaves usable authority. | Hostile Origin/preflight, CSRF attempts, renewal/logout/revocation and cookie scope; distinguish non-browser service credentials from cookie requirements. |
| L05: compatible interaction and bounded streams | Select REST/HTTP, unary/streaming gRPC, GraphQL, SSE, WebSocket or durable acceptance by task. Separately state HTTP version, encoding, client/proxy support, schema evolution and cancellation. | Message/frame/result limits, deadlines/retries, stream count, outbound buffer/slow-consumer policy, reconnect/resume retention and shutdown/drain deadline. | Protocol mismatch, schema break, slow-consumer memory growth, reconnect gaps/duplicates, permission changes during a stream. | Compatibility/schema tests, exhaust streams, pause consumers, cancel/disconnect/resume and drain; verify per-message authorization where needed and memory bounds. |
| L05/L07: bounded GraphQL demand if selected | Limit depth, breadth/aliases/batches, list sizes, query cost, resolver fan-out and N+1 separately. Consider trusted operation documents for controlled first-party clients. | Version-specific execution/cost limits plus downstream admission; a depth limit alone does not cap breadth or list cardinality. | Shallow wide expensive queries, alias/batch amplification, unbounded resolvers or sensitive errors. | Adversarial depth/breadth/batch/list/cost cases, query counts, cancellation and bounded memory; GraphQL is not automatically more efficient or private. |

Failure handling: keep failed transport/identity checks visible; repair the actual cause or stop the dependent action. A local HTTP hop or development CA is not evidence of production TLS, mTLS, DNS propagation, CDN isolation or multi-zone load balancing. Each inherited component needs its own current evidence.
