# SaaS engineering skills

| Role | Entry point | Use |
| --- | --- | --- |
| Frontend | [ui-ux-engineering](ui-ux-engineering/SKILL.md) | Components, pages, flows, applications and design systems; reproduce, adapt, explore or improve |
| Backend | [backend-engineering](backend-engineering/SKILL.md) | Design, implement, debug, optimize, review and migrate service/data/operating paths |

Give the task and available references or repository. Each skill inspects the actual stack, preserves constraints, chooses relevant procedures, implements authorized changes and reports verification. Small changes use a short working contract; complex work adds the necessary architecture and failure analysis.

The 1.1 revision removes repeated rules and replaces broad checklists with decision tables, worked failure traces and falsifiable probes. Current targeted validation: **46 independent checks PASS across six fresh contexts**; qualitative limitations are recorded. Read the [frontend revision](ui-ux-engineering/evals/expert-report.md) and [backend revision](backend-engineering/evals/expert-report.md). [Version 1.0 snapshots](../../quality/saas/../../quality/saas/version-history/1.0.0/snapshot.json) preserve the previous instructions; their evaluation results do not certify changed instructions.

The standards basis is ISO/IEC/IEEE 29148:2018 requirements traceability and 42010:2022 architecture concerns/relationships. Full normative conformance is unverified. See the role-specific [frontend](ui-ux-engineering/references/standards.md) and [backend](backend-engineering/references/coding-standards.md) coding notes.

The [frontend source register](ui-ux-engineering/references/sources.md) and [backend source register](backend-engineering/references/sources.md) record skills.sh discovery, inspected repositories, primary guidance, adoption and limitations. The backend [meet.md](backend-engineering/meet.md) remains the supplied acceptance source.

Each package has an assets/manifest.json and existing Node validators. Browser, Figma, database and deployment claims require actual corresponding capabilities. Local fixture evidence uses Node 24.12/SQLite 3.50.4; it does not establish every supported platform. No global installation or publishing permission follows from adding these files.

Shared revision cases live in ../../quality/saas/expert-evals/; original evidence remains version-attributed. Disposable browser profiles are excluded from distribution under [archive exclusions](../../quality/saas/../../quality/saas/layout.json).
