# Supplemental large-queue fixture

An original typed native TypeScript/CSS fixture, separate from the frozen evaluation cases. It uses1,000 deterministic synthetic records and paginates50rows into a scrollable semantic table. Search, selection across pages/filters, refresh, slow update, error/retry and stale indication work locally. The reused [latest-intent loader](../lab/state.ts) also guards a transport deliberately ignoring abort. No remote service is connected.

From the skill directory run `node scripts/heavy-lab.mjs`. It uses the already installed TypeScript compiler and Playwright/Chrome, installs nothing, and generates `app.js` only inside this fixture after a strict no-emit semantic check. Set `PLAYWRIGHT_MODULE`, `TYPESCRIPT_MODULE`, or `CHROME_PATH`, or pass `--browser PATH` and `--out DIR`, to use another existing installation.

The [pre-execution plan](plan.json) declares dataset, workload, gates and three runs. The report records build/source hashes, actual device/browser/cache/network/CPU conditions, raw input-event telemetry and CDP Performance/Memory snapshots. Input feedback mutation and next-animation-callback timing are separate from operation completion. Animation callbacks do not measure paint latency or INP. Scroll/resize wall times include automation overhead. The typing workload uses sequential browser key events15ms apart; refresh includes a synthetic650ms delay. Timing summaries are median/minimum/maximum of three local runs.

The initial harness failure and [instrumentation correction](../../../../../../quality/saas/v1.0/ui-ux-engineering/evals/evidence/heavy/correction.json) are retained. Live document nodes measure the pagination structural cap; CDP’s broader node counter is diagnostic and may include detached/uncollected nodes. The100ms median callback gate is a modest local diagnostic threshold, not a production SLO. These observations do not establish FPS, a memory leak, full accessibility conformance, multi-browser support, field performance or real-user percentiles.
