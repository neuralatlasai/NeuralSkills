# Read the chosen platform only

Activate after [DevOps](devops.md) identifies the provider and placement concern. Inputs: account/subscription/project, region/zone, product/SKU/plan, runtime/IaC versions, state authority and workload. Dependencies: actual provider documentation and deployed configuration; product names do not prove capabilities. Output provider-native changes and checked operating limits. Missing access stays UNVERIFIED; do not provision alternatives merely to fill coverage. Sources inspected 2026-11-06 are in the [register](source-register.md#devops-extension).

| Platform / selection | Mechanism and operating limit | Failure / probe |
| --- | --- | --- |
| AWS | Compare ECS/Fargate, Lambda or VM with EKS by execution model and required Kubernetes control. Inspect IAM role/trust, VPC/subnets/endpoints/NAT, ALB/NLB/Route53 or CloudFront, and chosen state service. Multi-AZ and multi-Region address different failure scopes. Recovery region needs independently available images, configuration, keys, network and capacity. | Drain tasks/nodes; remove one declared zone; separately isolate the primary region and critical dependencies. Verify role/tenant denial, IP/connection/compute headroom, state promotion/fencing, loss and usable recovery. An EKS control plane does not provide application/data HA automatically. |
| Azure | Compare Container Apps/App Service/Functions/VM with AKS; direct Kubernetes API/control is a selection reason. Scope managed identity/RBAC and VNet/private DNS/egress; verify actual SKU/region zone support. Pair Front Door/Traffic Manager/application routing with the selected database's recovery contract. | Test actual data-plane permissions, secret/identity rotation, revision rollout and zone/region loss. A successful role declaration is insufficient: verify deployed identity, scope and permitted/denied operations. Coordinate routing/state failover and deliberate failback. |
| Google Cloud | Compare Cloud Run service/job/worker, VM and GKE using lifetime, startup, concurrency, GPU/network and Kubernetes needs. Scope service accounts/workload identity and regional data. Cloud Run maximum instances can briefly be exceeded; enforce DB/session admission independently of autoscaling configuration. | Burst during revision coexistence and cold start; exhaust connection/quota safely. Verify rejection, pool wait and cleanup. Test regional failover against actual replication/authority; a multi-region frontend proves neither zero data loss nor immediate recovery. |
| Cloudflare | CDN/WAF/Workers for compatible edge execution; inspect Wrangler version/schema, compatibility date/flags, bindings, plan quotas and origin placement. KV permits stale reads and cached misses; choose suitable authoritative coordination such as Durable Objects for required per-object consistency. Cross-object atomicity needs its own mechanism. | Concurrent multi-location mutation/read, immediate revocation, hot objects, origin failure and bounded CPU/memory. CPU time differs from wall time; isolate memory is shared across concurrent requests. Stream bounded payloads. `waitUntil` is not a general durable-job guarantee. Verify residency/product contract rather than inferring it from edge proximity. |
| Other provider / private cloud | Map compute, identity, network, state/consistency, storage, quota, telemetry and recovery to actual documented components. Retain existing Nomad/systemd/PaaS where it meets requirements; portability has an implementation and operations cost. | Run the same declared failure and permission probes. Lack of a provider adapter means configuration and live behavior require discovery, not fabricated CLI/API examples. |

For every selected row, name concrete resources, owners, limits with units, expiration/rotation and recovery authority. Avoid a universal service catalogue or preselected region. Check current quota, service availability, price and compatibility at execution time; no account-level limits were measured during authoring.

Cross-region asynchronous replication permits a data-loss window; synchronous coordination adds latency and can sacrifice availability under partition. Inspect the chosen engine instead of assigning generic cloud guarantees. Define the last acknowledged durable effect, lag threshold, promotion/fencing condition, reconciliation and failback. Include data residency and credential/key recovery in that contract.

Local emulator, rendered IaC, provider validation, live deployment and observed incident recovery are distinct evidence. Regional and global claims require failure probes in the declared topology and workload; list unavailable probes explicitly.
